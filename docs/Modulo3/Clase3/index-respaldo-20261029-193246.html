El backend resume

El backend resume, Angular muestra.

Qué es un resumen del negocio

Un (o reporte) es un dato que no existe en ninguna fila de la base de datos: se calcula a partir de muchas filas. "Ingresos del mes" no está guardado en ninguna reserva; es la suma de valorTotal de las reservas confirmadas del mes.

Definición técnica. Un dato agregado es el resultado de aplicar una operación (sumar, contar, promediar, agrupar) sobre un conjunto de registros. Un endpoint de reporte devuelve esos resultados ya calculados, en lugar de los registros.

Explicación sencilla. Mariana no quiere las 9 facturas del mes: quiere el número de abajo. El backend le entrega el número de abajo.

En Colmena. GET /api/reportes/resumen responde un solo objeto con seis datos. El frontend no recibe ninguna reserva.

Por qué en el backend

Las tres razones de la pregunta, ahora con Colmena:

RazónSi se suma en AngularSi se calcula en el backend
RendimientoEl navegador descarga todas las reservas del mes (hoy 10; en diciembre, cientos) cada vez que se abre el panelViaja un objeto de seis datos
SeguridadPara sumar, Angular necesitaría poder leer todas las reservas: quien tenga ese permiso también vería quién reservó y cuánto pagóEl resumen tiene su propio permiso, REPORTES_VER, y no dice nombres
Una sola regla"Solo cuentan las confirmadas" quedaría escrito en Angular y en el backend; un día alguien cambia una y no la otraLa regla vive en ReporteServiceImpl

    🟨 Java · stream().filter(...) deja solo las reservas cuya fecha es igual a hoy y count() las cuenta.

    🟨 Java · mapToInt(Reserva::getValorTotal) convierte cada reserva en su valor y sum() los suma. Este es el "reduce" del practicante, pero del lado que conoce todas las reservas y las reglas.

import { Component, computed, inject, signal } from '@angular/core';
import { HttpErrorResponse } from '@angular/common/http';
import { mensajeDeError } from '../../core/errores';
import { pesos } from '../../core/formato';
import { Resumen, ReportesService } from '../../services/reportes.service';

@Component({
  imports: [],
  selector: 'app-panel',
  styleUrl: './panel.css',
  templateUrl: './panel.html',
})
export class Panel {
  private reportesService = inject(ReportesService);

  resumen = signal<Resumen | null>(null);
  error = signal<string | null>(null);

  pesos = pesos;
  mes = new Intl.DateTimeFormat('es-CO', { month: 'long', year: 'numeric' }).format(new Date());

  // El espacio con más horas llena la barra; los demás se miden contra él
  maximoHoras = computed(() => {
    const horas = this.resumen()?.ocupacionMes.map(o => o.horasReservadas) ?? [];
    return Math.max(1, ...horas);
  });

  constructor() {
    this.reportesService.resumen().subscribe({
      next: (datos) => this.resumen.set(datos),
      error: (error: HttpErrorResponse) => this.error.set(mensajeDeError(error))
    });
  }

  // 6 horas cuando el máximo es 8 -> 75 (por ciento del ancho)
  ancho(horas: number): number {
    return Math.round((horas / this.maximoHoras()) * 100);
  }
}

export interface Reserva {
  id: number;
  espacioId: number;
  espacioNombre: string;
  espacioTipo: TipoEspacio;
  usuarioId: number;
  usuarioNombre: string;
  fecha: string;

  horaFin: string;

// Lo único que envía el miembro: quién reserva, el valor y el estado los decide el backend
export interface NuevaReserva {
  espacioId: number;
  fecha: string;
  horaInicio: string;
  horaFin: string;
  asistentes: number;
  nota: string | null;
}

// La regla de cancelación en un solo lugar: solo lo CONFIRMADO que todavía no empieza.
// La usan Mis reservas y la Agenda; el backend la vuelve a verificar (409).
export function sePuedeCancelar(reserva: Reserva, ahora: Date): boolean {
  return reserva.estado === 'CONFIRMADA' && new Date(`${reserva.fecha}T${reserva.horaInicio}`) > ahora;
}

@Service()
export class ReservasService {
  private http = inject(HttpClient);
  private apiUrl = `${API_URL}/reservas`;

  private lista = signal<Reserva[]>([]);
  private cargandoSignal = signal(false);
  private errorSignal = signal<string | null>(null);

  reservas = this.lista.asReadonly();
  cargando = this.cargandoSignal.asReadonly();
  error = this.errorSignal.asReadonly();

  // POST /api/reservas: devuelve el Observable para que la página decida qué hacer
  crear(datos: NuevaReserva): Observable<Reserva> {
    return this.http.post<Reserva>(this.apiUrl, datos);
  }

  // GET /api/reservas/mias: el backend sabe quién es por el token
  cargarMias() {
    this.cargandoSignal.set(true);
    this.errorSignal.set(null);

    this.http.get<Reserva[]>(`${this.apiUrl}/mias`).subscribe({
      next: (datos) => {
        this.lista.set(datos);
        this.cargandoSignal.set(false);
      },
      error: (error: HttpErrorResponse) => {
        this.errorSignal.set(mensajeDeError(error));
        this.cargandoSignal.set(false);
      }
    });
  }

  // GET /api/reservas?fecha=AAAA-MM-DD (exige RESERVAS_VER_TODAS): la agenda de un día
  cargarDelDia(fecha: string) {
    this.cargandoSignal.set(true);
    this.errorSignal.set(null);
    const params = new HttpParams().set('fecha', fecha);

    this.http.get<Reserva[]>(this.apiUrl, { params }).subscribe({
      next: (datos) => {
        this.lista.set(datos);
        this.cargandoSignal.set(false);
      },
      error: (error: HttpErrorResponse) => {
        this.errorSignal.set(mensajeDeError(error));
        this.cargandoSignal.set(false);
      }
    });
  }

  // PATCH /api/reservas/{id}/cancelar
  cancelar(reserva: Reserva) {
    this.errorSignal.set(null);

    this.http.patch<Reserva>(`${this.apiUrl}/${reserva.id}/cancelar`, {}).subscribe({
      next: (actualizada) => {
        this.lista.update(actuales =>
          actuales.map(r => (r.id === actualizada.id ? actualizada : r))
        );
      },
      error: (error: HttpErrorResponse) => this.errorSignal.set(mensajeDeError(error))
    });
  }
}

La pregunta

Qué es

Definición técnica. Mass assignment (asignación masiva) es una vulnerabilidad que aparece cuando el framework copia automáticamente los campos de la petición en un objeto del sistema, y el atacante agrega campos que el desarrollador nunca quiso recibir: isAdmin, rol, saldo, activo. La defensa recomendada por OWASP es recibir la petición en un que solo tiene los campos que el usuario puede llenar, en vez de enlazarla directamente a la entidad.

Explicación sencilla. Es como un formulario en papel: si la oficina copia todo lo que el cliente escribió en la hoja, el cliente puede agregar una línea al final que diga "Cargo: gerente". Si la oficina solo copia las casillas impresas, esa línea extra se queda en la hoja.

const CLAVE_TOKEN = 'colmena_token';

// Lee el payload del JWT (la parte del medio). NO verifica la firma:
// eso solo lo puede hacer el backend, que es quien conoce la clave secreta.
function leerToken(token: string): ContenidoToken | null {
  try {
    const payload = token.split('.')[1];
    const base64 = payload.replace(/-/g, '+').replace(/_/g, '/');
    const bytes = Uint8Array.from(atob(base64), letra => letra.charCodeAt(0));
    return JSON.parse(new TextDecoder().decode(bytes));
  } catch {
    return null;
  }
}

  private http = inject(HttpClient);
  private router = inject(Router);

  private tokenSignal = signal<string | null>(localStorage.getItem(CLAVE_TOKEN));
  private errorSignal = signal<string | null>(null);
  private cargandoSignal = signal(false);

  private contenido = computed(() => {
    const token = this.tokenSignal();
    return token ? leerToken(token) : null;
  });

  sesionActiva = computed(() => {
    const contenido = this.contenido();
    return contenido !== null && contenido.exp * 1000 > Date.now();

  email = computed(() => (this.sesionActiva() ? this.contenido()!.sub : ''));

    this.errorSignal.set(null);
  }

  // Lo que comparten login y registro: enviar, guardar el token y entrar
  private entrar(url: string, cuerpo: Credenciales | NuevaCuenta) {
    this.errorSignal.set(null);
    this.cargandoSignal.set(true);

    this.http.post<RespuestaAuth>(url, cuerpo).subscribe({
      next: (respuesta) => {
        this.tokenSignal.set(respuesta.token);
        localStorage.setItem(CLAVE_TOKEN, respuesta.token);
        this.cargandoSignal.set(false);
        this.router.navigateByUrl('/espacios');
      },
      error: (error: HttpErrorResponse) => {
        this.cargandoSignal.set(false);
        this.errorSignal.set(mensajeDeError(error));
      }
    });
  }

  cerrarSesion() {
    this.tokenSignal.set(null);
    localStorage.removeItem(CLAVE_TOKEN);
    this.router.navigateByUrl('/login');
  }
}

export const APERTURA = '07:00';
export const CIERRE = '21:00';

export interface DatosReserva {
  fecha: string;
  horaInicio: string;
  horaFin: string;
  asistentes: number;

// '09:30' -> 570 (minutos desde la medianoche)
function minutos(hora: string): number {
  const [horas, mins] = hora.split(':').map(Number);
  return horas * 60 + mins;
}

// La fecha de hoy en el computador de quien usa la app, como 'AAAA-MM-DD'
export function hoyComoTexto(): string {
  const hoy = new Date();
  const mes = String(hoy.getMonth() + 1).padStart(2, '0');
  const dia = String(hoy.getDate()).padStart(2, '0');
  return `${hoy.getFullYear()}-${mes}-${dia}`;
}

// Los bloques de media hora del horario: ['07:00', '07:30', ..., '21:00']
export function bloquesDelDia(): string[] {
  const bloques: string[] = [];
  for (let m = minutos(APERTURA); m <= minutos(CIERRE); m += 30) {
    const horas = String(Math.floor(m / 60)).padStart(2, '0');
    bloques.push(`${horas}:${m % 60 === 0 ? '00' : '30'}`);
  }
  return bloques;
}

// Horas entre dos bloques: '09:00' a '10:30' -> 1.5. 0 si falta una hora o están invertidas.
export function horasEntre(horaInicio: string, horaFin: string): number {
  if (!horaInicio || !horaFin) {
    return 0;
  }
  const horas = (minutos(horaFin) - minutos(horaInicio)) / 60;
  return horas > 0 ? horas : 0;
}

// Devuelve la lista de errores. Lista vacía = se puede enviar.
export function validarReserva(datos: DatosReserva, capacidad: number, ahora: Date): string[] {
  const errores: string[] = [];

  if (!datos.fecha) {
    errores.push('Escoge la fecha');
  }
  if (!datos.horaInicio) {
    errores.push('Escoge la hora de inicio');
  }
  if (!datos.horaFin) {
    errores.push('Escoge la hora de fin');
  }
  if (errores.length > 0) {
    return errores;
  }

  if (minutos(datos.horaFin) <= minutos(datos.horaInicio)) {
    errores.push('La hora de fin debe ser posterior a la hora de inicio');
  }
  if (minutos(datos.horaInicio) < minutos(APERTURA) || minutos(datos.horaFin) > minutos(CIERRE)) {
    errores.push('El coworking abre de 7:00 a. m. a 9:00 p. m.');
  }
  if (minutos(datos.horaInicio) % 30 !== 0 || minutos(datos.horaFin) % 30 !== 0) {
    errores.push('Las reservas se hacen en bloques de 30 minutos (ej: 9:00 o 9:30)');
  }
  // 'AAAA-MM-DDTHH:mm' sin zona horaria se lee como hora local del computador
  if (new Date(`${datos.fecha}T${datos.horaInicio}`) < ahora) {
    errores.push('No puedes reservar en una fecha u hora que ya pasó');
  }
  if (!(datos.asistentes >= 1)) {
    errores.push('Debe asistir al menos 1 persona');
  } else if (datos.asistentes > capacidad) {
    errores.push(`Este espacio admite máximo ${capacidad} ${capacidad === 1 ? 'persona' : 'personas'}`);
  }

  return errores;
}

// Las reglas de RegistroRequest del backend, con sus mismos mensajes,
// más una que solo existe en pantalla: escribir dos veces la contraseña
export function validarCuenta(cuenta: NuevaCuenta, confirmacion: string): string[] {
  const errores: string[] = [];

  if (!cuenta.nombre) {
    errores.push('El nombre es obligatorio');
  }
  if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(cuenta.email)) {
    errores.push('El email no tiene un formato válido');
  }
  if (cuenta.password.length < 8) {
    errores.push('La contraseña debe tener al menos 8 caracteres');
  }
  if (cuenta.password !== confirmacion) {
    errores.push('Las contraseñas no coinciden');
  }

  return errores;
}

export type TipoEspacio = 'SALA_REUNIONES' | 'OFICINA_PRIVADA' | 'CABINA' | 'AUDITORIO';

export interface Espacio {
  id: number;
  nombre: string;
  tipo: TipoEspacio;
  capacidad: number;
  precioHora: number;
  descripcion: string | null;
  imagenUrl: string | null;

// Lo que envía la administración al crear o editar. El id y el estado los maneja el backend
export interface NuevoEspacio {
  nombre: string;
  tipo: TipoEspacio;
  capacidad: number;
  precioHora: number;
  descripcion: string | null;
  imagenUrl: string | null;

// Un horario ocupado de un espacio. No dice quién reservó: eso es privado.
export interface FranjaOcupada {
  horaInicio: string;
  horaFin: string;
}

export const NOMBRE_TIPO: Record<TipoEspacio, string> = {
  SALA_REUNIONES: 'Sala de reuniones',
  OFICINA_PRIVADA: 'Oficina privada',
  CABINA: 'Cabina',
  AUDITORIO: 'Auditorio'
};

@Service()
export class EspaciosService {
  private http = inject(HttpClient);
  private apiUrl = `${API_URL}/espacios`;

  private lista = signal<Espacio[]>([]);
  private cargandoSignal = signal(false);
  private errorSignal = signal<string | null>(null);

  espacios = this.lista.asReadonly();
  cargando = this.cargandoSignal.asReadonly();
  error = this.errorSignal.asReadonly();

  // GET /api/espacios: el backend decide si devuelve todos o solo los activos
  cargar() {
    this.cargandoSignal.set(true);
    this.errorSignal.set(null);

    this.http.get<Espacio[]>(this.apiUrl).subscribe({
      next: (datos) => {
        this.lista.set(datos);
        this.cargandoSignal.set(false);
      },
      error: (error: HttpErrorResponse) => {
        this.errorSignal.set(mensajeDeError(error));
        this.cargandoSignal.set(false);
      }
    });
  }

  // GET /api/espacios/{id}: lo usa la página Reservar
  obtener(id: number): Observable<Espacio> {
    return this.http.get<Espacio>(`${this.apiUrl}/${id}`);
  }

  // GET /api/espacios/{id}/ocupacion?fecha=AAAA-MM-DD: los horarios ya tomados ese día
  ocupacion(id: number, fecha: string): Observable<FranjaOcupada[]> {
    const params = new HttpParams().set('fecha', fecha);
    return this.http.get<FranjaOcupada[]>(`${this.apiUrl}/${id}/ocupacion`, { params });
  }

  // POST /api/espacios (exige ESPACIOS_GESTIONAR)
  crear(datos: NuevoEspacio): Observable<Espacio> {
    return this.http.post<Espacio>(this.apiUrl, datos);
  }

  // PUT /api/espacios/{id} (exige ESPACIOS_GESTIONAR)
  actualizar(id: number, datos: NuevoEspacio): Observable<Espacio> {
    return this.http.put<Espacio>(`${this.apiUrl}/${id}`, datos);
  }

  // PATCH /api/espacios/{id}/estado (exige ESPACIOS_GESTIONAR)
  cambiarEstado(espacio: Espacio, activo: boolean) {
    this.errorSignal.set(null);

    this.http.patch<Espacio>(`${this.apiUrl}/${espacio.id}/estado`, { activo }).subscribe({
      next: (actualizado) => {
        this.lista.update(actuales =>
          actuales.map(e => (e.id === actualizado.id ? actualizado : e))
        );
      },
      error: (error: HttpErrorResponse) => this.errorSignal.set(mensajeDeError(error))
    });
  }
}

    Qué es una

    Definición técnica. La revisión de código (code review) es la práctica de que otra persona del equipo lea un cambio antes de que se una a la rama principal, para encontrar defectos, riesgos y problemas de diseño, y para que el conocimiento del sistema no quede en una sola cabeza.     Diagnosticar

    Errores y señales

    El Panel se queda en el rectángulo gris para siempre

    • Síntoma: esqueleto infinito; en la pestaña Red no aparece resumen.
    • Causa probable: falta el .subscribe(...) en el constructor: el Observable de HttpClient no sale hasta que alguien se suscribe.
    • Cómo comprobarlo: si Red está vacía, la petición nunca salió.
    • Corrección: this.reportesService.resumen().subscribe({ next: ..., error: ... }).

    TS2339: Property 'r' does not exist on type 'Panel'

    • Cómo leerlo: "en la clase Panel no hay una propiedad r". La plantilla busca en la clase todo lo que no definió ella misma.
    • Causa: falta ; as r en @if (resumen(); as r), o se usó r fuera de las llaves del @if.

    El Panel o la Agenda muestran "No tienes permiso para realizar esta acción"

    • Causa probable: el token es de antes de un cambio de permisos, o la ruta no tiene permisoGuard y alguien sin el permiso llegó a la página (el backend respondió 403).
    • Cómo comprobarlo: en Red, la petición dice 403. Mira "Tu acceso" en el menú lateral: ¿tiene "Ver reportes"?
    • Corrección: cerrar sesión y volver a entrar; revisar el canActivate de la ruta.

    La Agenda de hoy sale vacía y el Panel dice 0

    • Causa probable: la base colmena_db se sembró otro día: las reservas "de hoy" son de ese día.
    • Corrección: borrar y crear colmena_db en pgAdmin y reiniciar el backend.

    El Registro crea la cuenta pero se queda en la misma página

    • Causa probable: entrar no llega a navigateByUrl, o el error de otra página tapa la pantalla.
    • Cómo comprobarlo: en Red, registro · 201. En la consola, ¿hay un error de JavaScript?
    • Corrección: revisar que next de entrar tenga las cuatro líneas del paso 1.

    Al editar un espacio, el formulario sale vacío y al guardar dice "Ya existe un espacio llamado…"

    • Causa probable: el input no se llama igual que el parámetro de la ruta (por ejemplo espacioId = input<string>() con la ruta :id). El Router no encuentra a quién entregarle el valor, el formulario cree que está creando y el POST choca con el nombre existente (409).
    • Corrección: el nombre del input y el del parámetro deben ser idénticos: id y :id.

    status 0 · "No pudimos conectarnos con el servidor…"

    • Causa: el backend no está corriendo en el puerto 8080 (o se cayó al arrancar: revisa su terminal).

    Dato agregado (resumen)
    resultado de sumar, contar o agrupar muchos registros; no está guardado en ninguna fila.
    el total al final del extracto del banco: no es un movimiento, es la suma de todos.
    Concepto 1 · ReporteServiceImpl
    Endpoint de reporte
    una ruta de la API que devuelve datos ya calculados en lugar de registros.
    pedirle al contador el balance del mes, no la caja de facturas.
    Concepto 1 · GET /api/reportes/resumen
    Fuente de verdad (una regla, un lugar)
    el único lugar del sistema donde está definida una regla o un dato; los demás lo consultan.
    el reglamento interno del coworking: hay una sola versión y todos la leen.
    Panel · Agenda (sePuedeCancelar)
    Presentación frente a negocio
    la lógica de presentación decide cómo se ve un dato; la de negocio decide cuál es el dato.
    el diseñador escoge el tamaño de la letra del precio; la gerente decide el precio.
    Panel · ancho()
    Mass assignment (asignación masiva)
    vulnerabilidad en la que el atacante envía campos extra (como rol) que el sistema copia sin querer en sus objetos.
    escribir "Cargo: gerente" al final de un formulario y que la oficina lo copie.
    Concepto 2 · RegistroRequest
    DTO (objeto de transferencia de datos)
    clase o record que define exactamente qué campos entran o salen por la API, separado de la entidad de la base de datos.
    el formulario impreso con casillas: solo se copia lo que tiene casilla.
    Concepto 2 · RegistroRequest · NuevaCuenta
    Registro público
    endpoint sin autenticación que crea cuentas con el rol de menor privilegio.
    la puerta de entrada al coworking: cualquiera se inscribe, pero nadie sale con la llave de la gerencia.
    Bloque 4 · /registro
    Extraer método (refactor)
    mover un bloque de código a un método con nombre y parámetros, y llamarlo desde donde estaba, sin cambiar el comportamiento.
    escribir una sola vez la receta de la masa y decir "masa básica" en cada receta que la usa.
    Bloque 4 · entrar() en auth.service.ts
    Input opcional de ruta
    un input() sin .required que recibe un parámetro de la URL si existe, o undefined si no.
    un formulario que viene en blanco o con los datos ya llenos, según te lo entreguen.
    Bloque 5 · EspacioForm.id
    Validación nativa del navegador

    la segunda lectura antes de enviar un correo importante.

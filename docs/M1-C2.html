02
Problema de negocio

Una sola pantalla no alcanza

El usuario necesita abrir la ficha exacta de Firulais —historial, dueño y próxima cita— sin recargar toda la aplicación.

Pregunta guía

¿Cómo llevas al usuario a otra pantalla con solo la información de Firulais y una URL compartible?

Necesidad real

VetCare seguirá creciendo

Inicio, listado, detalle, citas, dueños y login no deben terminar dentro de un único app.html gobernado por muchos @if.

Una vista gigante

  • Responsabilidades mezcladas.
  • Sin URL propia.
  • Sin enlaces directos.
  • Historial de navegación roto.

Una URL por vista

  • Páginas separadas.
  • Enlaces compartibles.
  • Botón Atrás funcional.
  • Arquitectura escalable.
Decisión

El Router de Angular cambia el componente según la URL, sin pedir otra página HTML ni recargar la aplicación.

03
Fundamentos

SPA y routing

La app carga una vez; la URL y el Router deciden qué vista ocupa el centro.

Definición técnica

SPA

Single Page Application: un único index.html y JavaScript redibujando contenido.

Explicación sencilla

Una carga

Angular cambia de pantalla sin descargar una página completa nueva.

Aplicación

Experiencia fluida

Como Gmail, Spotify web o Netflix.

index.html

Carga una vez.

URL

Expresa el destino.

Router

Busca coincidencia.

Componente

Redibuja la vista.

Routing

Mapea la URL actual a un componente: /mascotas abre el Listado; /mascotas/1 abre el Detalle del id 1.

Backend

@GetMapping("/mascotas/{id}") mapea una URL a un método.

Frontend

path: 'mascotas/:id' mapea una URL a un componente.

Lazy loading

Versión final consolidada

Convierte component en loadComponent

Qué harás: reemplazar la tabla anterior al final del proceso. Por qué: descargar cada página por demanda. Qué aprenderás: import dinámico.

VERSIÓN FINAL CONSOLIDADAsrc/app/app.routes.ts
import { Routes } from '@angular/router';

export const routes: Routes = [
  {
    path: '',
    loadComponent: () =>
      import('./pages/inicio/inicio').then(m => m.Inicio)
  },
  {
    path: 'mascotas',
    loadComponent: () =>
      import('./pages/mascotas-listado/mascotas-listado').then(m => m.MascotasListado)
  },
  {
    path: 'mascotas/:id',
    loadComponent: () =>
      import('./pages/mascota-detalle/mascota-detalle').then(m => m.MascotaDetalle)
  }
];

Los imports estáticos desaparecen porque cargarían las páginas desde el inicio. loadComponent espera hasta visitar la ruta; import(...) descarga; then selecciona la clase.

Error anticipado

Conservar imports estáticos anula el beneficio: el código ya habría sido cargado antes de ejecutar el import dinámico.

Verificación observable

Compruébalo en Network

Abre F12 → Network. La carga inicial debe ser menor; al visitar Mascotas aparece un archivo nuevo correspondiente al Listado.

Cuándo no usarlo

No aporta para un encabezado o pieza necesaria siempre y de inmediato. Lazy loading es criterio, no receta.

IA como copiloto

Generar rápido no reemplaza decidir

La versión de Angular, el patrón arquitectónico y el sistema visual deben aparecer tanto en el prompt como en la revisión.

Prompt de trabajo

“Genera las rutas de una app Angular 22 standalone con provideRouter, usando loadComponent para lazy loading y withComponentInputBinding para leer parámetros de ruta como @Input. Sin NgModule, sin RouterModule.”

Decisión técnica

La IA propone ActivatedRoute y subscribe. ¿Lo aceptas únicamente porque funciona?

Respuesta

No para esta arquitectura. @Input con withComponentInputBinding requiere menos código y reutiliza lo aprendido. Funcionar no prueba que una solución sea la más actual o mantenible.

Sintaxis vieja

*ngIf y *ngFor en lugar de @if y @for.

Arquitectura vieja

app.module.ts, @NgModule o RouterModule.forRoot.

CSS inconsistente

Colores sueltos en vez de variables del sistema.

Reto acumulativo

Revisa el diff antes de aceptar

Valida standalone, Angular 22, binding a inputs, conversión del id, lazy loading, estados de ausencia, accesibilidad de imágenes y uso de variables CSS.

01 · Recuento de la Clase 2

VetCare ya sabe navegar

La app pasó de una pantalla a tres páginas conectadas. Hoy partimos de esa arquitectura, no desde cero.

Una app de tres páginas

Inicio, Listado de mascotas y Detalle de cada mascota. El Router de Angular decide qué componente mostrar según la URL actual, sin recargar la página.

Las tres piezas del routing

app.routes.ts es la tabla URL → componente; <router-outlet> es el espacio donde se dibuja la página activa; routerLink navega sin recargar.

El id viaja en la URL

Al abrir Firulais, la URL cambia a /mascotas/1. MascotaDetalle recibe ese 1 con @Input() id, gracias a withComponentInputBinding() en app.config.ts. Es el mismo Input: esta vez el dato llega desde la URL.

Lazy loading

Las rutas cambiaron component: por loadComponent:. Cada página se descarga solo cuando el usuario la visita.

Un sistema de diseño compartido

styles.css centraliza --azul-principal, --espacio-md, --radio, --sombra y más. Flexbox organiza navegación y detalle; CSS Grid usa repeat(auto-fill, minmax(240px, 1fr)) para responder sin media queries.

i

Punto de partida

La navegación ya funciona. La deuda que quedó visible es otra: Listado y Detalle guardan copias separadas de las mismas mascotas.

04 · El problema real

Datos duplicados y componentes que no pueden avisar

VetCare crecerá hacia citas, dueños, login y facturación. Una arquitectura frágil se vuelve más costosa con cada pantalla.

Copias por página

  • Actualizar una mascota obliga a cambiar varios archivos.
  • Dos pantallas pueden mostrar valores distintos del mismo dato.
  • Un cambio no tiene cómo notificar a las demás vistas.

Una fuente compartida

  • El dato cambia en un único lugar.
  • Todas las pantallas leen el mismo estado.
  • Las vistas reaccionan cuando la fuente notifica un cambio.

La segunda pieza que falta

Hasta ahora el dato solo baja del Listado a mascota-card mediante @Input. El hijo puede mostrar información, pero todavía no puede avisar al padre: “el usuario marcó esta mascota como favorita”. Para eso necesitaremos un Output.

Para pensar

¿Alcanzan @Input y propiedades normales para sincronizar Listado, Detalle y navegación?

Ver respuesta

No: necesitamos comunicación hacia arriba y un estado capaz de notificar cambios.

@Input solo comunica de padre a hijo. Las tres pantallas no forman esa relación entre sí, y una propiedad normal no garantiza que Angular detecte y redibuje cada dependencia. Signals resuelve la notificación; un servicio resuelve el lugar compartido.

05 · Concepto central

¿Qué es el estado de una aplicación?

El estado conecta lo que pasó con lo que el usuario ve ahora.

Definición técnica

Estado es toda la información que puede cambiar con el tiempo y que determina lo que el usuario ve en pantalla en un momento dado.

Si un valor depende de lo que hizo el usuario —escribió, hizo clic o cargó datos— forma parte del estado: el texto de un buscador, un menú abierto o la lista de favoritos.

Ejemplo cotidiano

En un cajero, el estado incluye cuánto dinero queda disponible para retirar durante la sesión.

En VetCare

Qué mascotas existen y cuáles marcó el usuario como favoritas.

Estado local

  • Le pertenece a un componente.
  • A nadie más le importa.
  • Ejemplo: texto del buscador del Listado.

Estado compartido

  • Varias vistas lo leen o modifican.
  • No requiere relación padre-hijo.
  • Ejemplo: mascotas favoritas.
✓

Regla de oro

Estado local vive en el componente. Estado compartido vive en un servicio.

07 · Introducción a Signals

Una variable que sabe quién la está mirando

Signals convierten el cambio de datos en una notificación precisa.

Definición técnica

Una Signal es un contenedor de un valor que notifica automáticamente a quien lo esté usando cuando ese valor cambia.

En sencillo: es una variable “inteligente”. Guarda el dato, registra quién lo lee y avisa a esas partes para que se actualicen.

Propiedad normal

  • Guarda un valor.
  • Angular debe revisar qué pudo cambiar.
  • Es como buscar una aguja repasando todo el pajar.

Signal

  • Guarda el valor y conoce sus dependencias.
  • Notifica exactamente qué parte debe redibujarse.
  • Hace el cambio más predecible y localizado.
i

Aplicación profesional

Signals es el mecanismo oficial y moderno de Angular para estado reactivo. Para estado simple reemplaza patrones más pesados como BehaviorSubject. React tiene hooks de estado: la idea común es que los datos notifican sus cambios.

✓

Hacia dónde va Angular

El framework evoluciona para depender menos de revisar toda la app y más de las relaciones explícitas entre Signals y sus consumidores.

08 · Mecánica base

Crear, leer y actualizar una Signal

Primero dominamos la caja; después la conectamos a VetCare.

Paso 1

Crear una Signal con valor inicial

EjemploSignal mínima · TypeScript
import { signal } from '@angular/core';

contador = signal(0);

signal(0) crea una Signal cuyo valor inicial es 0. contador ya no es un número: es una caja que contiene un número.

Paso 2

Leer el valor llamando la Signal

LeerTypeScript y plantilla
console.log(contador());

La regla de los paréntesis

contador es la caja; contador() significa “abre la caja y dame el valor”. En HTML se lee igual: {{ contador() }}, nunca {{ contador }}.

Paso 3

Elegir entre set() y update()

ActualizarSignal mínima · TypeScript
contador.set(10);

contador.update(valorActual => valorActual + 1);
set()

Reemplaza el valor directamente. Úsalo cuando ya conoces el valor nuevo.

update()

Recibe el valor actual y devuelve el nuevo. Úsalo cuando el cambio depende del anterior; evita trabajar con un valor viejo.

!

Error típico #1 · Falta llamar la Signal

Qué sale: el HTML muestra algo como function o nada útil. Cómo se lee: Angular recibió la caja, no su contenido. Solución: usar contador().

10 · Estado derivado

computed(): una fórmula que nunca se desincroniza

La lista filtrada depende de las mascotas y del texto de búsqueda. No necesita su propia edición manual.

Definición técnica

computed() crea una Signal derivada: calcula su valor a partir de otras Signals y se recalcula solo cuando cambia alguna dependencia. Es de solo lectura; no tiene .set() ni .update().

Piensa en Excel: una celda con =A1+B1 cambia cuando cambian A1 o B1. No editas el resultado directamente.

Añadirsrc/app/pages/mascotas-listado/mascotas-listado.ts
import { Component, signal, computed } from '@angular/core';

// ...dentro de la clase MascotasListado, después de busqueda:

mascotasFiltradas = computed(() =>
  this.mascotas().filter(m =>
    m.nombre.toLowerCase().includes(this.busqueda().toLowerCase())
  )
);
i

Angular descubre las dependencias

La función lee this.mascotas() y this.busqueda(). Angular registra ambas sin configuración adicional y recalcula cuando cualquiera cambia. toLowerCase() permite que “firu” encuentre “Firulais”.

✓

Cuándo usarlo

Totales, contadores, promedios y listas filtradas son candidatos naturales. Al no guardar otra copia, no existe una versión derivada “vieja” que alguien olvidó actualizar.

13 · Comunicación hijo → padre

output(): el evento sube

La tarjeta detecta la intención. El dueño del estado decide qué cambio ejecutar.

Para pensar

Cuando el usuario toca el corazón, ¿quién debe decidir si la mascota pasa a favoritos: la tarjeta o el Listado?

Ver respuesta

La tarjeta detecta el clic, pero no debe administrar el estado compartido.

La tarjeta avisa hacia arriba. El Listado —y después el servicio— decide qué hacer. Así el componente visual no mezcla su responsabilidad con la lógica de negocio.

Definición técnica

Un Output es una propiedad de un componente que permite emitir eventos hacia el componente padre. Puede subir un dato o solo el aviso de que ocurrió algo.

Si Input es “recibir un pedido”, Output es “levantar la mano”. Un botón reutilizable suele emitir guardar, eliminar, marcar o seleccionar; no toma por sí mismo la decisión global.

i

API moderna

Hoy usamos output(). En tutoriales y respuestas antiguas verás @Output() x = new EventEmitter(): sigue funcionando, pero pertenece al patrón anterior.

Versión final consolidada

Agregar el Output y emitir desde el método del clic

Reemplazarsrc/app/components/mascota-card/mascota-card.ts
import { Component, Input, output } from '@angular/core';

@Component({
  selector: 'app-mascota-card',
  templateUrl: './mascota-card.html',
  styleUrl: './mascota-card.css'
})
export class MascotaCard {
  @Input() nombre = '';
  @Input() especie = '';
  @Input() edad = 0;
  @Input() foto = '';
  @Input() esFavorito = false;

  favoritoCambiado = output<void>();

  alClicFavorito(evento: Event) {
    evento.stopPropagation();
    evento.preventDefault();
    this.favoritoCambiado.emit();
  }
}
output<void>()

Declara el Output. void significa que no viaja un dato adicional: solo el aviso.

emit()

Dispara el evento para que quien escucha reaccione. La tarjeta no necesita saber qué hará el padre.

14 · Interacción accesible

Un corazón visible y comprensible

El icono comunica con color; ARIA comunica el mismo estado sin depender de la vista.

aria-pressed

Indica si el botón toggle está activo. Sin este estado, una persona que no ve el corazón rosa no sabe si la mascota ya es favorita.

aria-label

Describe la acción en palabras y cambia entre “Agregar” y “Quitar” según el estado.

Prefijo attr.

aria-pressed es un atributo HTML, no una propiedad JavaScript del elemento; el prefijo le dice a Angular cómo escribirlo.

El carácter Unicode ♥ no añade archivos ni librerías. El span permite animar y colorear el icono sin afectar todo el botón.

15 · Elementos anidados clicables

El clic que burbujea hasta el enlace

La tarjeta completa navega al Detalle y ahora contiene un botón. Un solo clic puede activar ambos elementos.

Para pensar

Si el usuario toca el corazón dentro de una tarjeta envuelta en <a [routerLink]>, ¿qué ocurre?

Ver respuesta

Se marca el favorito y, además, el enlace intenta navegar al Detalle.

El clic del botón sube por sus ancestros hasta el <a>. Ese mecanismo se llama event bubbling.

Definición técnica + modelo cotidiano

Event bubbling es la propagación de un evento del DOM desde el elemento donde nació hacia todos sus ancestros, activando sus manejadores.

Es como gritar en un pasillo: no solo escucha quien está frente a ti; el sonido sigue hacia atrás. En interfaces aparece con botones eliminar dentro de filas clicables, iconos dentro de tarjetas y checkboxes dentro de listas seleccionables.

Soluciónsrc/app/components/mascota-card/mascota-card.ts
alClicFavorito(evento: Event) {
  evento.stopPropagation();
  evento.preventDefault();
  this.favoritoCambiado.emit();
}
stopPropagation()

Corta la burbuja: el clic no sigue subiendo hacia el enlace que contiene la tarjeta.

preventDefault()

Cancela la acción predeterminada de navegación. Con ambas, el clic en el corazón se queda en el corazón.

Regla que no se rompe

El hijo jamás modifica directamente una propiedad del padre. La página escucha el Output y pide al servicio actualizar el estado. Es flujo unidireccional, compartido por Angular, React y Vue.

Criterio de ingeniería

¿Por qué no dejar que el hijo cambie directamente la variable del padre?

Ver respuesta

Porque el cambio dejaría de tener un origen predecible.

Sería rápido de escribir y difícil de depurar. Si cualquier componente puede modificar cualquier otro, en producción no sabrás quién causó el valor incorrecto. Con el flujo unidireccional, la actualización compartida pasa por el servicio. Es mantenibilidad, no burocracia.

Conexión con el servicio

Listado y Detalle son páginas hermanas. ¿Cómo comparten favoritos si no tienen Input ni Output entre ellas?

Ver respuesta

No se comunican directamente: ambas hablan con un tercero común.

Pasar el dato por la URL o inventar un canal entre hermanos no resuelve el diseño. El servicio es el punto estable que ambas pueden leer y actualizar.

17 · Estado compartido

El servicio separa datos de interfaz

La página decide cómo se ve; el servicio decide de dónde salen y cómo se manejan los datos.

Definición técnica

Un servicio Angular es una clase marcada con @Injectable que contiene lógica y datos que no pertenecen a un componente visual específico y que pueden ser usados por varios.

Carritos de compra, usuarios autenticados y catálogos suelen vivir en servicios. Es el principio de responsabilidad única de SOLID aplicado al frontend.

Spring Boot

  • @Service es singleton por defecto.
  • Existe una instancia para la aplicación.
  • Spring la inyecta con @Autowired.

Angular

  • providedIn: 'root' crea una instancia.
  • La comparte con quien la solicite.
  • El patrón es el mismo, del otro lado de la app.
Forma clásicaInyección por constructor · TypeScript
constructor(private mascotasService: MascotasService) {}
Forma modernaInyección con inject() · TypeScript
private mascotasService = inject(MascotasService);
i

Ambas formas son válidas

Usaremos inject() porque encaja con el estilo declarativo de Signals: las dependencias quedan como propiedades de la clase, sin lógica adicional en el constructor.

import { Injectable, signal, computed } from '@angular/core';

export interface Mascota {
  id: number;
  nombre: string;
  especie: string;
  edad: number;
  dueno: string;
  foto: string;
}

@Injectable({
  providedIn: 'root'
})
export class MascotasService {
  private listaMascotas = signal<Mascota[]>([
    { id: 1, nombre: 'Firulais', especie: 'Perro', edad: 4, dueno: 'Ana Torres', foto: 'https://placedog.net/600/400?id=1' },
    { id: 2, nombre: 'Michi', especie: 'Gato', edad: 2, dueno: 'Luis Pérez', foto: 'https://loremflickr.com/600/400/cat?lock=2' },
    { id: 3, nombre: 'Rocky', especie: 'Perro', edad: 6, dueno: 'María Gómez', foto: 'https://placedog.net/600/400?id=7' }
  ]);

  mascotas = this.listaMascotas.asReadonly();

  private idsFavoritos = signal<Set<number>>(new Set());

  totalFavoritos = computed(() => this.idsFavoritos().size);

  esFavorito(id: number): boolean {
    return this.idsFavoritos().has(id);
  }

  alternarFavorito(id: number) {
    this.idsFavoritos.update(actuales => {
      const nuevos = new Set(actuales);
      if (nuevos.has(id)) {
        nuevos.delete(id);
      } else {
        nuevos.add(id);
      }
      return nuevos;
    });
  }
}

20 · Decisiones del servicio

Tipos, encapsulación e inmutabilidad

La Signal notifica bien porque el servicio protege quién puede escribir y crea referencias nuevas.

interface Mascota

Declara el contrato de cada objeto. TypeScript ofrece autocompletado y detecta antes de ejecutar si falta, por ejemplo, dueno. Es comparable a un contrato de interfaz en Java.

asReadonly()

listaMascotas es privada; mascotas expone la misma Signal solo para lectura. Ningún componente externo puede llamar .set().

Set<number>

No permite ids repetidos y pregunta por pertenencia con .has(). Es el equivalente conceptual de HashSet en Java.

La línea decisiva

const nuevos = new Set(actuales); crea una referencia distinta antes de añadir o quitar el id.

Si se mutara el mismo Set con actuales.add(id) y se devolviera ese objeto, Angular podría comparar la misma referencia y concluir que no cambió nada. La pantalla no recibiría notificación.

ReglaDentro de MascotasService
const nuevos = new Set(actuales);
!

No mutar estructuras dentro de una Signal

Para Set usa new Set(actuales); para arreglos, [...arreglo]. Trabaja sobre la copia y devuélvela con .set() o .update().

!

Error típico #2 · El corazón no cambia

Qué sale: el clic no lanza error, pero el color nunca se actualiza. Cómo se lee: el contenido pudo mutar, pero la Signal no detectó una referencia nueva. Solución: clonar antes de modificar.

Number(this.id) conserva la conversión de la Clase 2: la URL entrega texto, mientras que las mascotas usan ids numéricos.

30 · Reto extra opcional

Persistir favoritos con effect()

Para grupos que avanzan más rápido o como tarea. No forma parte obligatoria de la evaluación.

El problema

Los favoritos viven en memoria. Al recargar la página, el navegador los pierde.

Un effect() vuelve a ejecutar un bloque cuando cambia alguna Signal leída adentro. A diferencia de computed(), no devuelve un valor: realiza efectos secundarios como guardar, registrar o sincronizar con localStorage.

Añadir en el servicio

Guardar los ids cada vez que cambien

Añadirsrc/app/services/mascotas.service.ts
import { Injectable, signal, computed, effect } from '@angular/core';

// dentro de la clase MascotasService, agregar un constructor:

constructor() {
  effect(() => {
    const idsActuales = [...this.idsFavoritos()];
    localStorage.setItem('vetcare-favoritos', JSON.stringify(idsActuales));
  });
}
i

Qué dispara el efecto

El bloque lee idsFavoritos(). Cada vez que esa Signal cambia, Angular ejecuta de nuevo la función y guarda la lista actualizada.

!

Error opcional · “injection context”

effect() necesita un contexto de inyección. Si se llama desde un método normal puede fallar. Colócalo en el constructor del servicio o componente.

31 · IA como copiloto

Pedir la API moderna y revisar el diff

Signals es más reciente que gran parte del código público. Una instrucción precisa evita que la IA regrese por defecto a patrones antiguos.

Prompt sugerido

“Genera un servicio Angular con providedIn: 'root' que exponga una lista de elementos como Signal de solo lectura (asReadonly()), con un computed() derivado, y un componente hijo que emita un evento hacia su padre usando la función output(), no @Output() con EventEmitter. Sin RxJS, sin BehaviorSubject.”

Validar la respuesta

La IA devuelve BehaviorSubject, .subscribe() y no usa Signals. ¿Lo aceptas porque funciona?

Ver respuesta

No sin evaluar si es la herramienta adecuada para este problema.

BehaviorSubject sigue siendo válido, pero para estado simple Signals es más directo y no exige subscribe()/unsubscribe() manual, una fuente común de fugas de memoria. Que compile no convierte la decisión en la mejor para el contexto.

  • Usa output(), no @Output() new EventEmitter().
  • No muta arreglos con .push() ni Set con .add() sobre el valor actual.
  • Lee cada Signal con paréntesis en el HTML.
  • No reemplaza @Input + withComponentInputBinding por ActivatedRoute.subscribe().
  • No llama effect() fuera de un contexto de inyección.
!

Disciplina profesional

La IA acelera la propuesta; tú sigues siendo responsable de revisar el diff, las APIs elegidas y la dirección del flujo de datos.

01 · Problema

VetCare ya no puede inventar sus datos

La recepcionista necesita ver y registrar información que de verdad quede en el backend.

Para pensar

¿Qué tendría que cambiar en MascotasService para mostrar lo que está guardado en la base de datos?

El arreglo de la Clase 3 estaba disponible de inmediato. Una respuesta de red no.

Ver respuesta

Angular debe pedir los datos por HTTP, esperar sin congelar la aplicación y actualizar el Signal cuando llegue la respuesta. Cambia el origen de los datos; no desaparece el estado centralizado.

El salto de esta clase

En las Clases 1–2 construiste Inicio, Listado y Detalle. En la Clase 3 centralizaste mascotas y favoritos con Signals. Ahora ese mismo servicio se conecta a Spring Boot.

Al terminar: podrás consultar y registrar mascotas y dueños desde Angular, y distinguir entre carga, fallo y datos disponibles.

Mercado Libre, Netflix o una app bancaria consultan un servidor para obtener información actualizada. VetCare necesita el mismo cambio.

02 · Modelo mental

Pedir no es lo mismo que tener

El mesero no lleva la comida en el bolsillo: toma el pedido y espera a la cocina.

Contrato

El backend define los nombres y la forma del JSON. El frontend consume ese contrato.

Petición → estado

HttpClient y Observable transportan la respuesta; un Signal conserva el valor que lee la pantalla.

Carga, error y datos

La interfaz informa lo que está pasando mientras el dato todavía no está disponible.

1 · Angular envía el pedido

MascotasService se suscribe a GET /api/mascotas. La vista sigue leyendo los Signals mientras espera.

2 · El backend atiende la petición

Controller recibe HTTP → Service aplica la lógica → Repository consulta la base de datos.

3 · La respuesta vuelve a Angular

Los registros recorren las capas de regreso y el Controller responde con 200 y JSON de MascotaResponse.

4 · El estado cambia la pantalla

next actualiza listaMascotas; el template que lee ese Signal se redibuja. Si la petición falla, se informa el error.

En el restaurante, cargando significa “el pedido está en preparación”; error, “no fue posible atenderlo”; datos, “el plato está servido”. Una respuesta correcta también puede traer una lista vacía: vacío no significa fallo.

i

Cada pieza tiene su responsabilidad

En VetCare, los componentes leen Signals y llaman métodos del servicio. HttpClient vive en los servicios de cada recurso. En Spring Boot, Controller recibe HTTP, Service aplica lógica y Repository accede a los datos.

04 · Herramienta

La petición comienza al suscribirse

HttpClient se integra con la inyección de Angular y devuelve Observables de RxJS.

HttpClient

Servicio de Angular para enviar peticiones HTTP. Aquí se inyecta dentro de MascotasService y DuenosService.

Observable de HTTP

Describe una petición pendiente. subscribe() la envía y recibe el dato en next o el fallo en error.

Signal

Siempre tiene un valor actual. Primero será []; después guardará el resultado de la petición.

Para pensar

Después de suscribirte a una petición HTTP, ¿se ejecuta primero el console.log que viene debajo o llega primero la respuesta?

Ver respuesta

El console.log se ejecuta primero; el programa continúa y la respuesta de red llega después a next. Crear el Observable con http.get() no envía por sí solo la petición: hace falta subscribe().

Para que inject(HttpClient) encuentre el servicio, regístralo una vez en la configuración. Conserva withComponentInputBinding(), que ya conecta parámetros de ruta con el componente de detalle.

Reemplazar · typescriptsrc/app/app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideRouter, withComponentInputBinding } from '@angular/router';
import { provideHttpClient } from '@angular/common/http';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes, withComponentInputBinding()),
    provideHttpClient()
  ]
};

provideHttpClient() habilita el cliente HTTP; provideRouter(...) mantiene el enrutamiento. Si omites el proveedor HTTP, falla la inyección. El texto del buscador sigue siendo un Signal local: no necesita una petición.

Reemplazar · typescriptsrc/app/services/mascotas.service.ts
import { Injectable, signal, computed, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';

export interface Mascota {
  id: number;
  nombre: string;
  especie: string;
  edad: number;
  dueno: string;
  foto: string;
}

@Injectable({
  providedIn: 'root'
})
export class MascotasService {
  private http = inject(HttpClient);
  private apiUrl = 'http://localhost:8080/api/mascotas';

  private listaMascotas = signal<Mascota[]>([]);
  mascotas = this.listaMascotas.asReadonly();

  private idsFavoritos = signal<Set<number>>(new Set());
  totalFavoritos = computed(() => this.idsFavoritos().size);

  constructor() {
    this.cargarMascotas();
  }

  cargarMascotas() {
    this.http.get<Mascota[]>(this.apiUrl).subscribe(datos => {
      this.listaMascotas.set(datos);
    });
  }

  esFavorito(id: number): boolean {
    return this.idsFavoritos().has(id);
  }

  alternarFavorito(id: number) {
    this.idsFavoritos.update(actuales => {
      const nuevos = new Set(actuales);
      if (nuevos.has(id)) {
        nuevos.delete(id);
      } else {
        nuevos.add(id);
      }
      return nuevos;
    });
  }
}

Un POST lleva información en el body. NuevaMascota describe lo que enviamos; Mascota, lo que consume la pantalla al recibir la respuesta. Reemplaza el servicio por su versión completa con GET, estados, POST y favoritos.

Reemplazar · typescriptsrc/app/services/mascotas.service.ts
import { Injectable, signal, computed, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';

export interface Mascota {
  id: number;
  nombre: string;
  especie: string;
  edad: number;
  dueno: string;
  foto: string;
}

export interface NuevaMascota {
  nombre: string;
  especie: string;
  raza: string;
  edad: number;
  duenoId: number;
}

@Injectable({
  providedIn: 'root'
})
export class MascotasService {
  private http = inject(HttpClient);
  private apiUrl = 'http://localhost:8080/api/mascotas';

  private listaMascotas = signal<Mascota[]>([]);
  private cargandoSignal = signal<boolean>(true);
  private errorSignal = signal<string | null>(null);

  mascotas = this.listaMascotas.asReadonly();
  cargando = this.cargandoSignal.asReadonly();
  error = this.errorSignal.asReadonly();

  private idsFavoritos = signal<Set<number>>(new Set());
  totalFavoritos = computed(() => this.idsFavoritos().size);

  constructor() {
    this.cargarMascotas();
  }

  // GET /api/mascotas
  cargarMascotas() {
    this.cargandoSignal.set(true);
    this.errorSignal.set(null);

    this.http.get<Mascota[]>(this.apiUrl).subscribe({
      next: (datos) => {
        this.listaMascotas.set(datos);
        this.cargandoSignal.set(false);
      },
      error: () => {
        this.errorSignal.set(
          'No pudimos conectarnos con el servidor de VetCare. Verifica que el backend esté corriendo en el puerto 8080.'
        );
        this.cargandoSignal.set(false);
      }
    });
  }

  // POST /api/mascotas
  crearMascota(nueva: NuevaMascota) {
    this.http.post<Mascota>(this.apiUrl, nueva).subscribe({
      next: (creada) => {
        this.listaMascotas.update(actuales => [...actuales, creada]);
      },
      error: () => {
        this.errorSignal.set('No pudimos registrar la mascota. Revisa los datos e intenta de nuevo.');
      }
    });
  }

  esFavorito(id: number): boolean {
    return this.idsFavoritos().has(id);
  }

  alternarFavorito(id: number) {
    this.idsFavoritos.update(actuales => {
      const nuevos = new Set(actuales);
      if (nuevos.has(id)) {
        nuevos.delete(id);
      } else {
        nuevos.add(id);
      }
      return nuevos;
    });
  }
}

http.post<Mascota>(this.apiUrl, nueva) envía el objeto como JSON. En next, update(actuales => [...actuales, creada]) construye otro arreglo y conserva los registros anteriores. La grilla reacciona sin recargar toda la página.

export class MascotasListado {

  mascotas = this.mascotasService.mascotas;
  cargando = this.mascotasService.cargando;
  error = this.mascotasService.error;

  alternarFavorito(id: number) {

  }

  registrarMascota(
    evento: SubmitEvent,
    inputNombre: HTMLInputElement,
    inputEspecie: HTMLInputElement,
    inputRaza: HTMLInputElement,
    inputEdad: HTMLInputElement,
    inputDuenoId: HTMLInputElement
  ) {
    evento.preventDefault();

    if (!inputNombre.value || !inputEspecie.value || !inputDuenoId.value) {
      return;
    }

    this.mascotasService.crearMascota({
      nombre: inputNombre.value,
      especie: inputEspecie.value,
      raza: inputRaza.value,
      edad: Number(inputEdad.value) || 0,
      duenoId: Number(inputDuenoId.value)
    });

    (evento.target as HTMLFormElement).reset();
  }
}

Crea src/app/services/duenos.service.ts. Un dueño se envía sin ID y se recibe con el ID asignado. El formulario pide nombre, apellido y documento; teléfono y email pueden quedar vacíos en esta práctica, y si escribes email debe ser válido.

Crear · typescriptsrc/app/services/duenos.service.ts
import { Injectable, signal, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';

export interface Dueno {
  id: number;
  nombre: string;
  apellido: string;
  documento: string;
  telefono: string;
  email: string;
}

export interface NuevoDueno {
  nombre: string;
  apellido: string;
  documento: string;
  telefono: string;
  email: string;
}

@Injectable({
  providedIn: 'root'
})
export class DuenosService {
  private http = inject(HttpClient);
  private apiUrl = 'http://localhost:8080/api/duenos';

  private listaDuenos = signal<Dueno[]>([]);
  private cargandoSignal = signal<boolean>(true);
  private errorSignal = signal<string | null>(null);

  duenos = this.listaDuenos.asReadonly();
  cargando = this.cargandoSignal.asReadonly();
  error = this.errorSignal.asReadonly();

  constructor() {
    this.cargarDuenos();
  }

  // GET /api/duenos
  cargarDuenos() {
    this.cargandoSignal.set(true);
    this.errorSignal.set(null);

    this.http.get<Dueno[]>(this.apiUrl).subscribe({
      next: (datos) => {
        this.listaDuenos.set(datos);
        this.cargandoSignal.set(false);
      },
      error: () => {
        this.errorSignal.set(
          'No pudimos conectarnos con el servidor de VetCare. Verifica que el backend esté corriendo en el puerto 8080.'
        );
        this.cargandoSignal.set(false);
      }
    });
  }

  // POST /api/duenos
  crearDueno(nuevo: NuevoDueno) {
    this.http.post<Dueno>(this.apiUrl, nuevo).subscribe({
      next: (creado) => {
        this.listaDuenos.update(actuales => [...actuales, creado]);
      },
      error: () => {
        this.errorSignal.set('No pudimos registrar el dueño. Revisa los datos (el documento y el email deben ser únicos).');
      }
    });
  }
}

Reemplazar · typescriptsrc/app/pages/mascotas-listado/mascotas-listado.ts
import { RouterLink } from '@angular/router';
import { MascotaCard } from '../../components/mascota-card/mascota-card';
import { Component, inject, signal, computed } from '@angular/core';
import { MascotasService } from '../../services/mascotas.service';
import { DuenosService } from '../../services/duenos.service';

@Component({
  selector: 'app-mascotas-listado',
  imports: [RouterLink, MascotaCard],
  templateUrl: './mascotas-listado.html',
  styleUrl: './mascotas-listado.css'
})
export class MascotasListado {
  private mascotasService = inject(MascotasService);
  private duenosService = inject(DuenosService);

  mascotas = this.mascotasService.mascotas;
  cargando = this.mascotasService.cargando;
  error = this.mascotasService.error;

  // Para el <select> del formulario: se llena con GET /api/duenos (mismo patrón de servicio)
  duenos = this.duenosService.duenos;

  busqueda = signal('');

  mascotasFiltradas = computed(() =>
    this.mascotas().filter(m =>
      m.nombre.toLowerCase().includes(this.busqueda().toLowerCase())
    )
  );

  esFavorito(id: number) {
    return this.mascotasService.esFavorito(id);
  }

  alternarFavorito(id: number) {
    this.mascotasService.alternarFavorito(id);
  }

  registrarMascota(
    evento: SubmitEvent,
    inputNombre: HTMLInputElement,
    inputEspecie: HTMLInputElement,
    inputRaza: HTMLInputElement,
    inputEdad: HTMLInputElement,
    selectDueno: HTMLSelectElement
  ) {
    evento.preventDefault();

    if (!inputNombre.value || !inputEspecie.value || !selectDueno.value) {
      return;
    }

    this.mascotasService.crearMascota({
      nombre: inputNombre.value,
      especie: inputEspecie.value,
      raza: inputRaza.value,
      edad: Number(inputEdad.value) || 0,
      duenoId: Number(selectDueno.value)
    });

    (evento.target as HTMLFormElement).reset();
  }
}

15 · Cierre

VetCare ya habla con su backend

Del arreglo escrito a mano a un recorrido de lectura y escritura verificable.

El problema que resolvimos

La interfaz mostraba información inventada dentro del frontend. Ahora consulta mascotas y dueños del backend, y permite registrar ambos recursos desde la aplicación.

1 · Contrato

Los campos enviados y recibidos deben coincidir con el backend; el servidor asigna los IDs.

2 · Petición → Signal

HttpClient pide o envía; subscribe recibe la respuesta y el servicio actualiza el estado de la vista.

3 · Estado visible

Una pantalla conectada debe informar espera, fallo y resultado, incluida una respuesta vacía.

Qué construiste: GET y POST en servicios por recurso, estados compartidos, formulario de mascota, página de Dueños y selector con datos reales. La arquitectura de la Clase 3 se conserva; cambia de dónde proviene la información.

Lo que ya está preparado en Spring Boot

Controller, permisos y datos de arranque: contexto técnico, no una segunda implementación.

MascotaController recibe las peticiones en /api/mascotas, delega en MascotaService y devuelve códigos HTTP. El POST usa @Valid y responde con 201 Created. PUT y DELETE existen en el controlador, pero no se implementan en el frontend de esta sesión.

Consultar · javasrc/main/java/com/devsenior/vetcare/controller/MascotaController.java
package com.devsenior.vetcare.controller;

import com.devsenior.vetcare.dto.MascotaRequest;
import com.devsenior.vetcare.dto.MascotaResponse;
import com.devsenior.vetcare.service.MascotaService;
import jakarta.validation.Valid;
import org.springframework.http.HttpStatus;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("/api/mascotas")
public class MascotaController {

    private final MascotaService mascotaService;

    public MascotaController(MascotaService mascotaService) {
        this.mascotaService = mascotaService;
    }

    @GetMapping
    public ResponseEntity<List<MascotaResponse>> listarTodos() {
        return ResponseEntity.ok(mascotaService.listarTodos());
    }

    @GetMapping("/{id}")
    public ResponseEntity<MascotaResponse> buscarPorId(@PathVariable Long id) {
        return ResponseEntity.ok(mascotaService.buscarPorId(id));
    }

    @PostMapping
    public ResponseEntity<MascotaResponse> crear(@Valid @RequestBody MascotaRequest request) {
        MascotaResponse creada = mascotaService.crear(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(creada);
    }

    @PutMapping("/{id}")
    public ResponseEntity<MascotaResponse> actualizar(
            @PathVariable Long id, @Valid @RequestBody MascotaRequest request) {
        return ResponseEntity.ok(mascotaService.actualizar(id, request));
    }

    @DeleteMapping("/{id}")
    public ResponseEntity<Void> eliminar(@PathVariable Long id) {
        mascotaService.eliminar(id);
        return ResponseEntity.noContent().build();
    }
}

Para pensar

¿Qué pasaría si GET /api/mascotas trajera diez mil registros de una vez?

Ver respuesta

Aumentarían el tamaño de la respuesta, el tiempo de carga y el trabajo de renderizado y memoria del navegador. La siguiente necesidad sería paginar desde el backend —por ejemplo, 20 o 50 registros por página—, no filtrar siempre todo el catálogo en el cliente.

Límites del código de la práctica
  • Los formularios se limpian antes de recibir la confirmación del POST. No hay estado independiente de guardado ni bloqueo de doble envío.
  • El mismo Signal de error se usa para GET y POST. Después de un POST fallido, una creación posterior puede llegar al backend y agregarse al arreglo, pero el error anterior permanece y la grilla sigue oculta hasta una nueva carga que lo limpie. Recarga para verificar el estado real.
  • El selector de dueños no distingue carga, fallo y lista vacía; solo comprueba la longitud del arreglo.
  • La interfaz Mascota solo declara un subconjunto de la respuesta. El tipado de TypeScript no valida los datos de red, y no deben suponerse valores no nulos sin revisar el contrato real.
  • Los favoritos siguen en memoria; una recarga los reinicia. El buscador filtra localmente los datos recibidos.
  • CORS no identifica usuarios. Las rutas abiertas se usan para este laboratorio; la autenticación y los entornos se trabajan en el Módulo 2.

Buenas decisiones que sí debes conservar

Una URL centralizada por servicio, métodos con nombres de intención como cargarMascotas y crearMascota, Signals de solo lectura para las vistas e inmutabilidad al actualizar listas. Cambiar de backend no debe obligar a reescribir los componentes.

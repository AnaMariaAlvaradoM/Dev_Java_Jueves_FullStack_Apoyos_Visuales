14
Ejercicio evolutivo

El catálogo transforma una lista de objetos en interfaz visible

La presentación queda preparada para cambiar después el origen de los datos sin rehacer la vista.

Problema

Si copiamos tres veces la tarjeta actual, ¿por qué las tres mostrarían a Firulais?

REEMPLAZAR TODOmascota-card.ts
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-mascota-card',
  imports: [],
  templateUrl: './mascota-card.html',
  styleUrl: './mascota-card.css'
})
export class MascotaCard {
  @Input() nombre = '';
  @Input() especie = '';
  @Input() edad = 0;
}
REEMPLAZAR TODOsrc/app/app.html
<h1>Catálogo de {{ nombreClinica }}</h1>

@if (mascotas.length === 0) {
  <p>No hay mascotas registradas.</p>
} @else {
  @for (m of mascotas; track m.nombre) {
    <app-mascota-card
      [nombre]="m.nombre"
      [especie]="m.especie"
      [edad]="m.edad">
    </app-mascota-card>
  }
}

nombre="Firulais"

  • Texto literal.
  • Siempre igual.

[nombre]="m.nombre"

  • Conexión de datos.
  • Cambia en cada iteración.

Cierre con criterio

¿Por qué separar la tarjeta de mascota en un componente propio si también podríamos escribirla directamente en la página?

Porque una pieza aislada puede reutilizarse, probarse y modificarse sin duplicar código. Esa decisión prepara el sistema para crecer.

01 · Necesidad de negocio

Del catálogo a la ficha individual

La navegación aparece porque el usuario necesita llegar a información específica sin perder el contexto.

Para pensar

El usuario hace clic en Firulais para ver su historial, dueño y próxima cita. ¿Cómo lo llevamos a otra pantalla con solo esa información, sin recargar toda la aplicación?

Piensa qué tendría que cambiar: ¿todo el documento o solo la vista central?

Ver respuesta

El Router de Angular cambia la vista según la URL sin recargar la página completa.

La primera intuición suele ser crear otro HTML y enlazarlo con un vínculo normal. En una aplicación Angular hay un solo documento base: el Router decide qué componente mostrar y conserva la experiencia continua de una SPA.

✓

Evidencia de esta clase

VetCare evolucionará de un catálogo único a tres vistas navegables y bien diseñadas: Inicio → Listado → Detalle.

Lo que ya construimos y por qué importa hoy

i

Mapa del curso

VetCare ya cuenta con backend en Java, Spring Boot, JWT y base de datos. Angular construye el frontend que consumirá esa API; la conexión real llegará en la Clase 4.

Para pensar

En una frase, ¿qué es Angular y para qué lo usamos?

Ver respuesta

Angular es un framework de Google para construir interfaces de aplicaciones web con TypeScript.

Puede parecer “el frontend” o una herramienta para páginas web, pero además organiza el código en piezas, ofrece inyección de dependencias y trae un CLI, ng, para generar el esqueleto. Cumple en el frontend un papel comparable al de Spring Boot en el backend.

🧱HTML

La estructura del componente: lo que aparece en pantalla.

🎨CSS

La presentación: cómo se ve y responde visualmente.

⚙️TypeScript

La lógica: datos y comportamiento del componente.

Un componente es un pedazo de pantalla reutilizable: botón, tarjeta o tabla. Como un ladrillo LEGO, es autónomo y permite construir interfaces grandes combinando piezas pequeñas.

Estado inicial de mascota-card

La tarjeta creada en la Clase 1 recibe sus datos desde afuera con @Input. Este archivo ya existe y se conserva como punto de partida.

Leer · existentesrc/app/components/mascota-card/mascota-card.ts
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-mascota-card',
  templateUrl: './mascota-card.html',
  styleUrl: './mascota-card.css'
})
export class MascotaCard {
  @Input() nombre = '';
  @Input() especie = '';
  @Input() edad = 0;
}

@Input() marca una propiedad como entrada. Igual que los parámetros de un método en Java, permite que la misma tarjeta represente distintas mascotas. Más adelante reutilizaremos la idea para recibir un dato desde la URL.

Catálogo al cerrar la Clase 1

En este archivo existente, @for recorre la lista y entrega a cada tarjeta los valores que necesita.

Leer · existentesrc/app/app.html
<h1>Catálogo de {{ nombreClinica }}</h1>

@for (m of mascotas; track m.nombre) {
  <app-mascota-card
    [nombre]="m.nombre"
    [especie]="m.especie"
    [edad]="m.edad">
  </app-mascota-card>
}

El bloque completo renderiza una tarjeta por mascota. La interpolación muestra datos; el property binding los pasa a entradas; @for repite; @if muestra contenido solo cuando se cumple una condición.

Sintaxis de referencia

  • {{ dato }}: interpolación; muestra un dato en el HTML.
  • [propiedad]="valor": property binding; asigna un valor a una propiedad o @Input.
  • @for (x of lista; track x.id) { ... }: repite un bloque por elemento.
  • @if (condicion) { ... }: muestra un bloque si se cumple la condición.
03 · El problema

Una sola pantalla no alcanza

Una aplicación real necesita inicio, listado, detalle y, más adelante, citas, dueños y acceso.

🏠Inicio

La entrada y el llamado principal.

🐾Listado + detalle

Explorar y consultar una mascota concreta.

📅Lo que sigue

Citas, dueños y acceso al sistema.

Decisión de arquitectura

¿Qué ocurriría si inicio, listado, detalle, citas y login vivieran en el mismo app.html, mostrando y ocultando pedazos con @if?

Ver respuesta

Podría funcionar al principio, pero se volvería inmantenible.

Un archivo gigante rompe la separación de responsabilidades. Tampoco ofrece URLs propias, enlaces directos a una mascota ni una navegación atrás confiable. La solución profesional es una vista por URL y un Router que decida qué mostrar.

Una plantilla gigante

Estado manual, muchas condiciones, difícil de probar y compartir.

Vistas enrutadas

URLs propias, responsabilidades separadas, navegación nativa y crecimiento ordenado.

04 · Conceptos base

SPA y routing: una vista que cambia con la URL

Primero entendemos el mecanismo; después escribimos código.

⚡SPA · definición técnica

Single Page Application: carga un solo index.html y JavaScript reescribe su contenido según las acciones del usuario.

🧭Routing · definición técnica

Mecanismo que decide qué componente se muestra según la URL actual.

Explicación sencilla

El navegador carga la aplicación una vez. Después Angular sustituye la vista central, sin pedir un documento HTML completo en cada cambio.

Aplicación profesional

Gmail, Spotify web y Netflix cambian de vista sin el parpadeo de una recarga completa. VetCare seguirá el mismo modelo.

URL /mascotasSolicitud de navegación
→
RouterConsulta la tabla de rutas
→
ListadoComponente que aparece

La URL /mascotas/1 mostrará el detalle de la mascota con id 1. En el backend, @GetMapping("/mascotas/{id}") mapea una URL a un método; el Router aplica el mismo patrón en el frontend y mapea una URL a un componente.

06 · Diseño visual

Un sistema de diseño antes de construir páginas

La coherencia visual es una decisión de arquitectura de interfaz, no maquillaje final.

🎨Paleta de VetCare

Azules serenos y confiables para la interfaz que construye el proyecto.

↔️Espaciado

Escala consistente en múltiplos de 8 px.

◒Tipografía y forma

Lectura clara, radios y sombras reutilizables.

Un sistema de diseño reúne decisiones visuales reutilizables: paleta, espaciado, tipografía y sombras. Es el equivalente a un manual de marca; evita que cada vista parezca un producto distinto.

Las variables CSS ofrecen un único lugar de verdad. Cuando cambie la identidad visual, se actualiza una variable y toda la aplicación responde.

07 · Construcción incremental

Reorganizar VetCare en páginas

Cada vista se vuelve un componente de página; las piezas reutilizables permanecen en components/.

Pieza · components/

Ladrillo reutilizable, como mascota-card. Puede vivir dentro de varias páginas.

Página · pages/

Pantalla completa a la que se llega por una URL, como listado o detalle.

Separar páginas de piezas mantiene responsabilidades claras: las piezas se reutilizan y las páginas son destinos de navegación.

Paso 1 · Crear la página Inicio

Ejecuta el comando desde la raíz vetcare/. El CLI crea la carpeta y cuatro archivos standalone.

Ejecutar · raíz del proyectoTerminal · vetcare/

Paso 2 · Definir la lógica de Inicio

El HTML usará routerLink; por eso el componente standalone debe importar RouterLink.

Editar · creado por CLIsrc/app/pages/inicio/inicio.ts
import { Component } from '@angular/core';

La regla standalone es explícita: cada componente declara en imports todo lo que usa su plantilla. Si falta RouterLink, el enlace interno no funcionará correctamente.

08 · Reutilización

Vestir la tarjeta una sola vez

mascota-card es una pieza reutilizable: su comportamiento y estilo permanecen encapsulados.

La misma tarjeta podría aparecer en el listado, el perfil del dueño o una búsqueda. Por eso recibe datos por entradas y mantiene su CSS en un archivo propio.

Paso 1 · Recibir la foto

Añadimos un cuarto @Input con el mismo patrón que nombre, especie y edad.

Editar · añadir entradasrc/app/components/mascota-card/mascota-card.ts
import { Component, Input } from '@angular/core';

@Component({
  selector: 'app-mascota-card',
  templateUrl: './mascota-card.html',
  styleUrl: './mascota-card.css'
})
export class MascotaCard {
  @Input() nombre = '';
  @Input() especie = '';
  @Input() edad = 0;
  @Input() foto = '';
}

El componente permanece genérico: no conoce a Firulais ni a Michi; solo representa los valores que recibe.

Paso 2 · Mostrar imagen y datos

La foto ocupa la zona superior y el texto queda agrupado debajo.

Reemplazarsrc/app/components/mascota-card/mascota-card.html
<div class="card">
  <img class="card-foto" [src]="foto" [alt]="'Foto de ' + nombre">
  <div class="card-cuerpo">
    <h3 class="card-nombre">{{ nombre }}</h3>
    <p class="card-datos">{{ especie }} · {{ edad }} años</p>
  </div>
</div>

[src]="foto" aplica property binding a la imagen. El [alt] describe la foto si no carga y permite que un lector de pantalla comunique su contenido.

i

Decisión consciente

NgOptimizedImage puede mejorar la carga en producción, pero exige tamaños fijos y configuración adicional. No se usa hoy porque desviaría el objetivo de routing.

Paso 3 · Dar forma a la tarjeta

La superficie blanca, la sombra suave y el recorte consistente preparan una grilla profesional.

09 · Cascarón de la SPA

<router-outlet> y navegación con routerLink

La barra permanece; el contenido central cambia según la URL.

Las páginas y la tarjeta ya existen. Ahora app deja de guardar la lista y asume una sola responsabilidad: ser el cascarón con navegación y outlet.

Paso 1 · Limpiar app.ts

Importamos las dos piezas que utilizará la plantilla raíz.

Reemplazarsrc/app/app.ts
import { Component } from '@angular/core';
import { RouterOutlet, RouterLink } from '@angular/router';

@Component({
  selector: 'app-root',
  imports: [RouterOutlet, RouterLink],
  templateUrl: './app.html',
  styleUrl: './app.css'
})
export class App {}

RouterOutlet habilita el hueco donde aparecerá la página activa. RouterLink convierte enlaces internos en navegación sin recarga.

Paso 2 · Construir el cascarón

La barra queda fuera del outlet y, por tanto, permanece visible en todas las rutas.

Reemplazarsrc/app/app.html
<nav class="barra">
  <span class="marca">🐾 VetCare</span>
  <div class="barra-links">
    <a routerLink="/" class="barra-link">Inicio</a>
    <a routerLink="/mascotas" class="barra-link">Mascotas</a>
  </div>
</nav>

<main class="contenido">
  <router-outlet></router-outlet>
</main>

La barra vive fuera del outlet y no cambia. Dentro del outlet, el Router dibuja Inicio, Listado o Detalle. Ese marco fijo con un centro variable es el corazón de la SPA.

Paso 3 · Estilizar el cascarón

Flexbox distribuye la marca y los enlaces; un ancho máximo conserva márgenes cómodos.

Reemplazarsrc/app/app.css

  padding: var(--espacio-sm) var(--espacio-lg);
  box-shadow: var(--sombra);
}

  color: #ffffff;
  font-weight: 700;
  font-size: 1.2rem;
}

.barra-links {
  display: flex;
  gap: var(--espacio-md);
}

  color: #ffffff;
  text-decoration: none;
  font-weight: 500;

}

justify-content: space-between separa la marca de los enlaces. max-width evita contenido pegado a los extremos. El hover de opacidad mantiene el mismo lenguaje de respuesta visual que el botón y las tarjetas.

Decisión técnica

¿Por qué no usar un <a href="/mascotas"> normal?

Ver respuesta

routerLink navega dentro de la SPA; href solicita de nuevo toda la página.

Aunque ambos parecen enlaces, href recarga index.html, puede perder estado y produce parpadeo. Para navegación interna en Angular usamos routerLink.

Paso 4 · Probar la navegación

Inicia el servidor desde la raíz para observar el cambio de URL y el outlet.

Ejecutar · raíz del proyectoTerminal · vetcare/
ng serve

Abre http://localhost:4200. La barra azul debe aparecer; al elegir “Mascotas”, la URL cambia a /mascotas sin recarga y el botón Atrás del navegador funciona.

!

Error: router-outlet no es un elemento conocido

Se lee como “Angular no reconoce la etiqueta”. Falta importar RouterOutlet en app.ts.

!

Error: routerLink no navega

Si no hace nada o recarga la página, el Router no controla el clic. Importa RouterLink en el componente cuya plantilla usa el enlace.

10 · Parámetros de ruta

Una página de detalle para cualquier mascota

La URL transporta el id; el componente lo recibe y encuentra el registro correspondiente.

El Listado ya construye enlaces como /mascotas/1. Ahora la página Detalle debe leer ese 1. Antes de hacerlo, necesitamos definir la tabla que relaciona URLs y componentes.

Dónde vive el routing

  • src/app/app.routes.ts: tabla de rutas, inicialmente vacía.
  • src/app/app.config.ts: configuración donde provideRouter(routes) activa el Router.

Paso 1 · Leer la configuración existente

Este archivo fue creado por ng new. No se modifica todavía; lo observamos para comprender cómo se enciende el routing.

Leer · sin modificarsrc/app/app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideRouter } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes)
  ]
};

provideRouter(routes) activa el Router en toda la app y le entrega la tabla de destinos. En el modelo mental, es darle a la recepcionista su lista de consultorios.

Paso 2 · Definir la primera tabla de rutas

Reemplaza el arreglo vacío por tres rutas directas. Esta versión intermedia permite entender el mapeo antes de optimizarlo.

Reemplazar · versión intermediasrc/app/app.routes.ts
import { Routes } from '@angular/router';
import { Inicio } from './pages/inicio/inicio';
import { MascotasListado } from './pages/mascotas-listado/mascotas-listado';
import { MascotaDetalle } from './pages/mascota-detalle/mascota-detalle';

export const routes: Routes = [
  { path: '', component: Inicio },
  { path: 'mascotas', component: MascotasListado },
  { path: 'mascotas/:id', component: MascotaDetalle }
];

path: '' representa la raíz y muestra Inicio. mascotas abre el Listado. mascotas/:id envía cualquier id al mismo componente Detalle.

:

Qué significa :id

Es una parte variable, no la palabra literal “id”. En /mascotas/1 vale 1; en /mascotas/2 vale 2. Una sola ruta sirve para todas las mascotas.

Para pensar

El componente Detalle es uno solo. ¿Cómo sabe si debe mostrar a Firulais, Michi, Rocky o una mascota futura?

Ver respuesta

Recibe el id de la URL y con él busca la mascota.

Pasar la mascota completa funciona entre componentes cercanos, pero una URL necesita una identidad estable. Hoy ese id consulta una lista local; en la Clase 4 permitirá llamar GET /mascotas/1. La recepción moderna reutiliza @Input.

Paso 3 · Conectar parámetros con inputs

Agrega withComponentInputBinding() para que un parámetro como :id llegue automáticamente al @Input del mismo nombre.

Editar · añadir bindingsrc/app/app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideRouter, withComponentInputBinding } from '@angular/router';
import { routes } from './app.routes';

export const appConfig: ApplicationConfig = {
  providers: [
    provideRouter(routes, withComponentInputBinding())
  ]
};

Sin esta función, @Input() id quedaría vacío. La alternativa histórica usa ActivatedRoute y una suscripción manual; funciona, pero añade código y conceptos que aquí no hacen falta.

Paso 4 · Implementar la lógica de Detalle

El componente recibe el id como texto y busca la mascota correspondiente en la lista local.

Reemplazar · versión consolidadasrc/app/pages/mascota-detalle/mascota-detalle.ts
import { Component, Input } from '@angular/core';
import { RouterLink } from '@angular/router';

@Component({
  selector: 'app-mascota-detalle',
  imports: [RouterLink],
  templateUrl: './mascota-detalle.html',
  styleUrl: './mascota-detalle.css'
})
export class MascotaDetalle {
  @Input() id = '';

  private mascotas = [
    { id: 1, nombre: 'Firulais', especie: 'Perro', edad: 4, dueno: 'Ana Torres', foto: 'https://placedog.net/600/400?id=1' },
    { id: 2, nombre: 'Michi', especie: 'Gato', edad: 2, dueno: 'Luis Pérez', foto: 'https://loremflickr.com/600/400/cat?lock=2' },
    { id: 3, nombre: 'Rocky', especie: 'Perro', edad: 6, dueno: 'María Gómez', foto: 'https://placedog.net/600/400?id=7' }
  ];

  get mascota() {
    return this.mascotas.find(m => m.id === Number(this.id));
  }
}

@Input() id recibe el parámetro. Number(this.id) convierte el texto de la URL antes de comparar. El getter mascota devuelve el registro cuyo id coincide y mantiene la plantilla enfocada en presentar.

!

Error silencioso: "1" !== 1

Todo valor de URL llega como texto. Si se omite Number(...), find no encuentra la mascota porque la comparación estricta entre texto y número es falsa.

11 · Rendimiento

Lazy loading: cargar cada página cuando se necesita

Con tres vistas casi no se nota; con cuarenta, descargar todo al inicio vuelve lenta la aplicación.

Pregunta de negocio

Si un usuario solo entra al Inicio, ¿tiene sentido descargar de inmediato el código de reportes, facturación y configuración que quizá nunca visitará?

Ver respuesta

No: cada página puede descargarse justo cuando se visita.

La aplicación no tiene que cargar todo por defecto. Lazy loading reduce la descarga inicial y se vuelve especialmente valioso cuando el sistema crece.

Definición técnica

Lazy loading es cargar un recurso en el momento en que se necesita. En routing, el código de una página se descarga al navegar a su URL.

Ejemplo cotidiano

Un buffet no sirve todos los platos al entrar; entrega el plato pedido cuando se necesita. El navegador hace lo mismo con cada vista.

Paso 1 · Convertir las rutas a carga diferida

Reemplaza component por loadComponent. Esta es la versión final consolidada de la tabla.

Reemplazar · versión finalsrc/app/app.routes.ts
import { Routes } from '@angular/router';

export const routes: Routes = [
  {
    path: '',
    loadComponent: () =>
      import('./pages/inicio/inicio').then(m => m.Inicio)
  },
  {
    path: 'mascotas',
    loadComponent: () =>
      import('./pages/mascotas-listado/mascotas-listado').then(m => m.MascotasListado)
  },
  {
    path: 'mascotas/:id',
    loadComponent: () =>
      import('./pages/mascota-detalle/mascota-detalle').then(m => m.MascotaDetalle)
  }
];

Los imports estáticos de las páginas desaparecen porque obligarían a cargarlas al inicio. loadComponent entrega una función; import(...) descarga el archivo al activar la ruta y .then(...) selecciona la clase exportada.

✓

Cómo verificarlo

En las herramientas del navegador, abre Network. Carga Inicio y luego entra a Mascotas: debe aparecer una nueva descarga correspondiente al listado justo en ese momento.

?

Cuándo no aporta

No conviene diferir algo necesario siempre y de inmediato, como el encabezado común. Lazy loading brilla en páginas que no todos visitan: reportes, administración o configuración.

12 · IA responsable

La IA propone; el desarrollador valida

La versión de Angular y las decisiones de arquitectura deben quedar explícitas en el prompt y en la revisión.

La IA genera rutas, componentes y estilos con rapidez, pero suele mezclar patrones antiguos: *ngIf, RouterModule.forRoot o ActivatedRoute con suscripciones.

Prompt de trabajo

“Genera las rutas de una app Angular 22 standalone con provideRouter, usando loadComponent para lazy loading y withComponentInputBinding para leer parámetros de ruta como @Input. Sin NgModule, sin RouterModule.”

Antes de pedir código, decide el patrón y la versión. Después compara la respuesta con las restricciones y con el código que ya existe.

Criterio profesional

La IA devuelve un detalle que lee el id con ActivatedRoute y .subscribe(...). ¿Se acepta solo porque funciona?

Ver respuesta

No se acepta sin evaluar si coincide con la arquitectura actual y el objetivo de la clase.

ActivatedRoute puede funcionar, pero aquí @Input y withComponentInputBinding ofrecen menos código y reutilizan un concepto conocido. El criterio está en escoger una solución mantenible, no en aceptar cualquier salida ejecutable.

1Sintaxis

Rechaza *ngIf y *ngFor si el proyecto usa @if y @for.

2Arquitectura

Descarta app.module.ts y @NgModule en una aplicación standalone.

3Tipos

Verifica Number(id); una comparación texto-número falla silenciosamente.

4Diseño

Evita colores aislados; exige reutilizar las variables del sistema visual.

∆

Disciplina de revisión

Lee el diff antes de aceptar. Comprueba imports, versión, patrón de routing, conversión de tipos, estados vacíos y coherencia visual.
